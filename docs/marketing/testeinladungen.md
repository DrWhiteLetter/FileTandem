## Deutscher Community-Beitrag

**Fünf Tester gesucht: SFTP/SCP-Dateimanager direkt in VS Code**

Ich entwickle FileTandem für Menschen, die Projektdateien auf einen Server übertragen und dabei in VS Code bleiben möchten. Lokale und entfernte Ordner stehen nebeneinander; Transfers laufen über SFTP/SCP, Remote-Dateien lassen sich im Editor bearbeiten. Für SFTP braucht der Server keinen VS Code Server.

Ich suche fünf Leute, die den ersten Verbindungsaufbau und einen kleinen Testtransfer ausprobieren. Besonders interessiert mich: Ist klar, wohin die Datei übertragen wird? Wo ist die Bedienung umständlich? Würdet ihr das in eurem Alltag verwenden?

Kostenlos, quelloffen (MIT), Oberfläche auf Deutsch und Englisch. VS Code Desktop ab 1.140.0 erforderlich. Bitte zuerst mit entbehrlichen Dateien in einem Testordner ausprobieren.

Installation: https://marketplace.visualstudio.com/items?itemName=RootShellForge.filetandem

Feedback: https://github.com/DrWhiteLetter/FileTandem/issues/new?template=first-transfer.yml

## English community post

**Looking for five testers: a dual-pane SFTP/SCP file manager for VS Code**

I'm building FileTandem for developers who transfer project files to a server and want to stay in VS Code. Browse local and remote folders side by side, transfer files over SFTP/SCP and edit remote files in the editor. SFTP access does not require VS Code Server on the target.

I'd love five people to try connecting and transferring a small test file. Was the destination clear? Where did you get stuck? Would this fit your workflow?

Free and open source (MIT), with English and German UI. Requires VS Code Desktop 1.140.0 or later. Please start with disposable files in a test directory.

## Rückmeldungen bearbeiten

- Rückmeldung bestätigen; bei Fehlern fehlende Versionsangaben und minimale Schritte erfragen.
- Mit Testdaten nachstellen; Datenverlust-/Überschreibprobleme zuerst untersuchen.
- Erwartetes Verhalten, Lösung oder nächsten Prüfschritt im Issue erklären. Keine unbelegten Fertigstellungstermine zusagen.
- Gelöste Probleme mit Version im Changelog nennen und Tester nach Veröffentlichung auf die Korrektur hinweisen.
- Nach fünf Rückmeldungen auswerten: Verbindung gelungen, erster Transfer gelungen, größte Hürde, erneute Nutzung. Daraus die nächsten Änderungen ableiten.

Versand, öffentliche Antworten und Bewertungen erfolgen nicht automatisch.

# M1-06 – Ansichtszustand

`getState`/`setState` sichern Pfade, Sortierung je Bereich, Breite, Queue und Anzeige versteckter Dateien. Ein WebviewPanelSerializer stellt die Oberfläche nach Fensterneustart wieder her. Persistierter Zustand wird auf erlaubte, begrenzte UI-Werte projiziert; Zugangsdaten, Verbindungsparameter und beliebige Pfade werden nicht übernommen. `retainContextWhenHidden` wird nicht gesetzt.

Die Application-Sitzung bleibt unabhängig vom DOM-/Panel-Lifecycle im Speicher (maximal 100 Demo-Sitzungen). Verbergen erzeugt keine neue Verbindung. Nach Extension-Host-Neustart erscheint eine restaurierte Sitzung getrennt; ausschließlich eine ausdrückliche Demo-Aktion wechselt den Zustand. Echte SSH-Verbindungen werden hier überhaupt nicht angelegt.

07.10.2026, macOS arm64, Node 22.13.1, VS Code 1.140.0: `npm run quality` mit 22 Unit-Tests und React-DOM-Test bestanden. Der DOM-Test liest gespeicherte Sortierung und prüft anschließend persistierten Ordnerwechsel und Queue-Zustand, ohne Verbindungsnachricht. Unit-Test verwirft unbekannte Pfade/Versionen und zusätzliche Geheimnisse. Echter Extension-Host/Webview-Handshake bestanden. Vollständige native Fensterneustart-Bedienabnahme bleibt als Teil der M6-Bedienmatrix offen.

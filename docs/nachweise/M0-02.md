# M0-02 – Ausführungsort nachweisen

Datum: 7. Oktober 2026. Implementierungscommit: `feat(M0-02): verify desktop execution and local file access` (dieser Nachweis gehört zum Commit).

**Status: Umsetzung und lokaler Nachweis vorhanden; Remote-SSH-Abnahme wegen inkompatibler Server-Laufzeit offen. M0-02 bleibt bis zum erfolgreichen echten Remote-Test unabgehakt.**

## Umsetzung

- Manifest: ausschließlich `extensionKind: ["ui"]`, Node-Einstieg, kein Browser-Einstieg.
- Vor Dateizugriff Prüfung von `Extension.extensionKind` und lokalem Extension-URI. Eine Übersteuerung auf Workspace-Ausführung wird abgefangen.
- Command `xscp.verifyLocalFile`: bewusste Auswahl mit `showOpenDialog` und `defaultUri: Uri.file(homedir())`; ausschließlich lokale `file:`-URIs ohne Authority, Query oder Fragment.
- Node.js liest die ausgewählte reguläre Datei über einen geöffneten Handle mit 64-KiB-Puffer und berechnet SHA-256. Handle wird auch bei Fehlern geschlossen. Größen-/Zeitstempeländerungen während des Lesens ergeben einen Fehler; dies ist keine atomare Dateisystem-Snapshot-Garantie.
- Lokaler Ausgabekanal protokolliert Dateiquelle, Datei, Bytezahl, Hash und Laufzeitumgebung; keine Dateiinhaltübertragung in die Webview. Der Kanal erhält Daten nur bei bewusst ausgeführtem Nachweisbefehl.
- Webview bezeichnet die lokale Quelle als „Lokal · Mein Rechner“; Host bestätigt die Ausführungsart über den vorhandenen lokalen Nachrichtenkanal. Bei Remote-Fenstern wird der Workspace von dieser Quelle abgegrenzt.

macOS 26.6.2 / Darwin 25.6.0, Apple Silicon arm64; Entwicklungs-Node.js 22.13.1, npm 10.9.2; installierter VS Code Desktop 1.140.0 (über `VSCODE_TEST_EXECUTABLE` verwendet; der Download-Fallback bleibt auf 1.139.1 fixiert). Remote-SSH-Erweiterung ist installiert. Docker, Podman, Colima, Lima und Multipass sind in der geprüften Shell nicht verfügbar; kein freigegebener isolierter SSH-Testhost bekannt. Vorhandene persönliche SSH-Zugänge wurden nicht verwendet.

```sh
npm run check
VSCODE_TEST_EXECUTABLE="/Applications/Visual Studio Code.app/Contents/MacOS/Code" npm test
```

Der automatisierte lokale Test ruft die exportierte Prüffunktion mit einer bewusst vom Desktop-Teststarter vorgegebenen Datei-URI auf. Er ersetzt keine Prüfung des nativen Auswahldialogs im Remote-Fenster. Die Prüffunktion und der Befehl verwenden denselben Node-Lesepfad.

## Remote-SSH-Prüfung abschließen

Nur einen freigegebenen isolierten Testserver verwenden; dieser muss einen VS Code Server unterstützen. Ein SFTP-only-Server reicht für Remote-SSH nicht. Auf dem Desktop eine kleine Testdatei mit eindeutigem Inhalt anlegen, deren vollständiger Pfad auf dem Testserver nicht existiert. SHA-256 mit dem Systemwerkzeug ermitteln (macOS: `shasum -a 256 <Testdatei>`).

1. In einem normalen Development Host den Nachweisbefehl ausführen, die Desktop-Datei auswählen und Hash/Bytezahl/Hostname protokollieren.
2. Die Debug-Konfiguration **xScp: Remote-SSH-Ausführungsort prüfen** starten. SSH-Hostalias und existierenden absoluten Remote-Testordner eingeben. Remote-SSH muss lokal installiert und aktiviert sein; diese Konfiguration deaktiviert es nicht.
3. Verbindungsaufbau abwarten. **Developer: Show Running Extensions** prüfen: xScp läuft im lokalen UI Extension Host. Eventuelle `remote.extensionKind`-Übersteuerungen entfernen.
4. Im Remote-Fenster denselben Nachweisbefehl ausführen. Die Auswahl muss das Desktop-Dateisystem zeigen; dieselbe Desktop-Testdatei auswählen. Ausgabe: `extensionKind: ui`, `local: true`, `windowRemoteName: ssh-remote`, Desktop-Hostname, identischer Pfad und Hash.
5. „Lokal · Mein Rechner“ und den Hinweis auf den getrennten Remote-Workspace prüfen. Ergebnis, Server-/VS-Code-Versionen und Einschränkungen hier ergänzen; erst dann M0-02 abhaken.

Zusätzlich ist der automatische Host-Test für Remote-SSH vorbereitet:

```sh
# Remote-SSH in das getrennte Testprofil installieren, falls noch nicht vorhanden:
"/Applications/Visual Studio Code.app/Contents/Resources/app/bin/code" \
  --extensions-dir "$PWD/.vscode-test/extensions" \
  --install-extension ms-vscode-remote.remote-ssh

XSCP_TEST_REMOTE_AUTHORITY="ssh-remote+<isolierter-testhostalias>" \
XSCP_TEST_REMOTE_FOLDER="/absoluter/testordner" \
VSCODE_TEST_EXECUTABLE="/Applications/Visual Studio Code.app/Contents/MacOS/Code" \
npm test
```

Der Remote-Modus öffnet einen echten `vscode-remote:`-Workspace und fordert `env.remoteName === "ssh-remote"`. Der Zufallsmarker bleibt auf dem Desktop, sein erwarteter Hash und Desktop-Hostname kommen vom lokalen Teststarter. Ein simuliertes `remoteName` gilt nicht als Nachweis. Die Remote-Testkonfiguration wurde nach Freigabe eines Servers ausgeführt; Ergebnis und notwendige Testverschärfung stehen im folgenden Nachtrag.

## Grenzen und Quellen

`env.remoteName` beschreibt das Fenster und ist auch im lokalen Host eines Remote-Fensters gesetzt. Es beweist allein keine Remote-Ausführung. Das API-Feld `Extension.extensionKind` berücksichtigt die VS-Code-Zuordnung einschließlich Nutzerübersteuerungen. [VS-Code-API](https://code.visualstudio.com/api/references/vscode-api).

UI-Erweiterungen werden lokal installiert und ausgeführt. [Offizielle Remote-Extension-Anleitung](https://code.visualstudio.com/api/advanced-topics/remote-extensions). Die Auswahl mittels lokalem `file:`-Startpfad ist vorbereitet; das tatsächliche Dialogverhalten im Remote-Fenster bleibt zu prüfen.

Kein Zugriff auf Remote-Workspace-Dateien als Desktop-Quelle, keine Browser-Unterstützung, keine SSH-Verbindung durch xScp in diesem Item. Windows/Linux, UNC, WSL und Dev Containers sind nicht geprüft. Cross-Host-Editor-Provider folgen in M0-08. Die vollständige Fertig-Bedingung erfordert die oben noch offene erfolgreiche Remote-SSH-Abnahme.

## Nachtrag: freigegebener SSH-Testserver geprüft

Am 7. Oktober 2026 hat der Nutzer einen vorhandenen produktionsnahen Testserver ausdrücklich für diesen Nachweis freigegeben. Die Prüfung war auf die Anmeldung, Abfrage von Laufzeitinformationen und den Remote-SSH-Verbindungsversuch begrenzt. Keine Änderungen an Anwendungsdateien oder Betriebssystempaketen. Zugangsdaten sind weder in diesem Nachweis noch im Repository abgelegt.

Umgebung: Ubuntu 18.04.6 LTS, Linux-Kernel 4.15.0, x86_64, glibc 2.27. Desktop: VS Code 1.140.0, Remote-SSH 0.128.0 im getrennten Testprofil. SSH-Passwortanmeldung erfolgreich; bash, tar, curl/wget und `/tmp` vorhanden. Die bereits bekannte SSH-Hostidentität wurde normal geprüft; die Host-Key-Prüfung blieb aktiv. Ein temporärer lokaler SSH-Control-Socket ermöglichte die Wiederverwendung der angemeldeten Verbindung ohne Passwortdatei.

VS Code meldet beim echten Remote-Verbindungsversuch: **The remote host does not meet the prerequisites for running VS Code Server**. Die von Microsoft dokumentierten Linux-Voraussetzungen umfassen Kernel >= 4.18 und glibc >= 2.28; der angebotene Server liegt unter beiden Grenzen. [Offizielle Linux-Voraussetzungen](https://code.visualstudio.com/docs/remote/linux).

Der ursprüngliche Remote-Test gab zunächst Exitcode 0 zurück, obwohl der Serverstart scheiterte: `env.remoteName` und eine `vscode-remote:`-Workspace-URI sind schon bei angeforderter, aber fehlgeschlagener Verbindung vorhanden. Der Desktop-Marker wurde in diesem fehlgeschlagenen Remote-Fenster lokal mit identischem Hash und Hostnamen gelesen; dies zählt **nicht** als vollständige Remote-Abnahme.

Der Test fordert nun zusätzlich einen erfolgreichen `workspace.fs.stat` des Remote-Testordners. Wiederholung gegen denselben Server ergibt korrekt Exitcode 1 wegen fehlendem Remote-Dateisystem-Provider (`ENOPRO`). Damit wird eine fehlgeschlagene Remote-Verbindung nicht mehr als bestanden ausgewiesen. Lokale Host-Tests bestehen weiterhin.

VS Code hat beim Verbindungsversuch Bootstrap-Dateien für die aktuelle Version im Benutzerverzeichnis unter `.vscode-server` angelegt/vorgefunden. Bestehende Serverdateien wurden nicht entfernt. Der SSH-Control-Master und die temporäre lokale SSH-Konfiguration wurden nach der Prüfung geschlossen bzw. entfernt. Kein Passwort wurde persistiert.

**Nächster erforderlicher Nachweis:** denselben Test auf einem freigegebenen Server ausführen, der die aktuellen VS-Code-Server-Voraussetzungen erfüllt. Ein Betriebssystem-/glibc-Upgrade oder eine Sysroot-Nachrüstung auf dem angebotenen Server gehört nicht zu M0-02 und wurde nicht vorgenommen. Dieser Nachtrag und die strengere Testprüfung gehören zum Commit `test(M0-02): require a reachable remote workspace and record SSH result`.

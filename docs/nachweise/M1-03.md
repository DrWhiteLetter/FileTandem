# M1-03 – Webview-Nachrichten

7. Oktober 2026. Commit: `feat(M1-03): validate and isolate webview session messages`.

Manager-Panel aus dem Extension-Einstieg in VS-Code-Adapter ausgelagert. Application hält Demo-Sitzungen getrennt von der Darstellung; Shared-Protokoll Version 1 mit type, Request-ID und nativer Sitzungs-ID. Jeder Panelcallback ist an genau eine bekannte Sitzung gebunden. Whitelist erlaubt nur ready, refresh und fest definierte Demo-Szenarien; keine Pfad-/SSH-/Credential-/Exec-Nachrichten. Exakte Eingabefelder, Tokenlängen, Typen und Szenarien werden geprüft, Trust/Host vor jeder Nachricht erneut geprüft. 256 jüngste Request-IDs werden für Wiederholungsabwehr gehalten; das ist kein späterer Replay-Schutz für destruktive Produktoperationen.

Outbound wird auf öffentliche Darstellungsinformationen reduziert. Webview akzeptiert nur passende Response-Version/ID/Sitzung und validierte Boolesche Orts-/Szenarioinformationen. Session-ID stammt aus kontrollierter HTML-Meta, Assets lokal, Nonce-CSP, kein Inline-Code oder generischer Shellkanal. React rendert Dateinamen später als Text.

`npm run quality`: 21 Unit-Tests, Lint, Syntax und Build bestanden. Protokolltest weist fremde Sessions, Credentials/Zusatzfelder, exec, falsche Version/IDs/Szenarien und Wiederholungen ab. Echter VS-Code-1.140.0-Test wartet erstmals auf den tatsächlich vom nonce-geschützten Webviewscript gesendeten und validierten Ready-Handshake; bestanden. Damit reicht ein bloßer Tab-Nachweis hier nicht mehr.

Grundlage: [Webview-Sicherheit](https://code.visualstudio.com/api/extension-guides/webview). Nachrichten-ID/Session-Regeln und Domain-/Application-Schnittstellen sind eigene Festlegungen.
